ConwayLife Sprint 2 (Java Swing)

Introduction

GAME OF LIFE DI CONWAY
Goal: Evoluzione del sistema base (Sprint 1) dotandolo di una Graphical User Interface (GUI) desktop tramite le librerie standard Java Swing.

Requirements

R2  L’utente umano deve poter:
     - specificare la configurazione iniziale della griglia del gioco	
     - vedere l’evoluzione del gioco in forma opportuna (GUI Desktop)
     - fermare e far ripartire l’evoluzione del gioco
     - pulire (a gioco fermo) la configurazione della griglia del gioco

Requirement analysis

L'introduzione di un'interfaccia grafica impone una separazione netta tra il Core di Business (la logica sviluppata nello Sprint 1) e la Presentazione. I nuovi componenti software sono:

  • GUI (View): Componente basato su javax.swing (JFrame, JPanel, JButton) per mappare visivamente la matrice bidimensionale.
  • Controller: Entità che orchestra l'interazione tra i pulsanti dell'utente (Start, Stop, Clear) e la classe Life del dominio.

Problem analysis

L'architettura adotta il pattern MVC (Model-View-Controller). Il problema critico in applicazioni desktop è mantenere l'interfaccia reattiva. Il ciclo infinito di calcolo delle generazioni di Conway non può essere eseguito sul thread della GUI (Event Dispatch Thread di Swing), altrimenti la finestra si bloccherebbe ("freeze"). È necessario introdurre un Thread separato che gestisca il loop temporale (Thread.sleep) e aggiorni la view in modo asincrono (es. tramite SwingUtilities.invokeLater).

Test plans

La logica core è già stata validata nello Sprint 1. Il testing della GUI avviene a livello di sistema (System Testing) verificando manualmente che i comandi utente producano il corretto avvio, arresto e reset della griglia senza bloccare l'applicazione.

Project

Il progetto riutilizza le classi del dominio (ICell, Life) senza alcuna modifica al codice sorgente, dimostrando il successo della Clean Architecture impostata nello Sprint 1. Il package devices è stato esteso con i componenti Swing.

Testing

I test unitari (JUnit) della logica core mantengono la loro validità e copertura. Non sono previsti test automatizzati per i componenti grafici Swing in questa fase.

Deployment

Generazione di un Fat JAR eseguibile in ambiente locale (Desktop) che include dipendenze e GUI.

Maintenance

Il limite di questo approccio è il forte accoppiamento alla macchina locale (Monolite Desktop). Il sistema non è utilizzabile via rete, rendendo necessaria una transizione verso architetture web (Sprint 3).
