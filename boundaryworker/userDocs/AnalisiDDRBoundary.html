Analisi del problema DDRBoundary

Requirements

Costruire un sistema software che comanda un Differential Drive Robot (DDR) in modo che, partendo dalla posizione iniziale HOME, il robot si sposti lungo il perimetro di una stanza rettangolare vuota. Il DDR si deve fermare quando tornato in HOME.

Il DDR e' anche sensibile ai dati rilevati da un Radar. Quando il Radar rileva un 'intruso' a distanza minore di DMIN:

  • se il DDR si sta muovendo, si ferma fino a che il Radar non rileva piu' un intruso cosi' vicino;
  • se il DDR e' fermo in HOME, ruota su se stesso fino a che l'intruso scompare.

Analisi dei requisiti

Goal: formalizzare le entita' del sistema escludendo le ambiguita' del linguaggio naturale, esprimendole in un linguaggio comprensibile a un computer (dichiarazioni Java + modello qak).

Entita' formalizzate

DDR — le mosse base, dichiarate come interfaccia:

public interface IRobotBasicMoves {
    void forward( int time )  throws Exception;
    void backward( int time ) throws Exception;
    void left( int time )     throws Exception;
    void right( int time )    throws Exception;
    void halt()               throws Exception;
}

Il DDR e' fornito dal simulatore VirtualRobot26 (servizio via WebSocket), che non va modificato.

Stanza — ambiente rettangolare vuoto di dimensioni note (L > H), formalizzato come matrice di celle di dimensione DR x DR (DR = diametro del robot, unita' di misura):

public class Room {
    int[][] room;       // griglia di occupazione (una cella = DR x DR)
    int nr;             // nr*DR < L  (lunghezza)
    int nc;             // nc*DR < H  (larghezza)
    int HOMEx = 0;      // HOME come zona, non come punto
    int HOMEy = 0;
}

Radar — sensore (su Raspberry PicoW) che invia stringhe della forma:

distance( DIRECTION, D )
   DIRECTION : valore da 0 a pi-greco, al momento fisso a pi/2
   D         : distanza misurata (intero)

Struttura: sistema distribuito su 3 nodi

  • nodo del servizio VirtualRobot26 (il DDR);
  • nodo del componente applicativo boundaryworker;
  • il PicoW che realizza il Radar.

Trattandosi di componenti logicamente (micro)servizi a scambio di messaggi, formalizziamo la struttura con il linguaggio qak.


Un modello dei requisiti

Il boundaryworker e' il componente centrale: proattivo (induce il DDR a percorrere il perimetro) e reattivo (reagisce ai dati del radar). Lo modelliamo come QActor. 

//boundaryworker_sprint0Req.qak
System ddrboundary

Request  step      : step(TIME)
Reply    stepdone  : stepdone(V)            for step
Reply    stepfailed: stepfailed(DURATION,CAUSE) for step
Dispatch move      : move(M)                "M = l|r|a|d|h"

Event    intruderClose : intruderClose(D,DIR)   "radar: D < DMIN"
Event    intruderGone  : intruderGone()         "radar: D ≥ DMIN"

Context ctxboundary       ip [host="localhost"  port=8120]
Context ctxrobotservice26 ip [host="127.0.0.1"  port=8125]   //stesso nodo

QActor boundaryworker context ctxboundary
              withobj room using "location/Room.java" {
    //proattivo: boundary walk    reattivo: intruder events
    ...
}

QActor radaractor context ctxradar {
    //interazione con il PicoW: legge la distanza e invia eventi al boundaryworker

Domande aperte al committente

D1. Interruzione: alla ricezione di intruderClose mentre il DDR e' in moto,
    si ferma immediatamente o completa la mossa atomica (step) in corso?

D2. Ripresa: alla ricezione di intruderGone, il robot continua dal punto in cui
    si era fermato o ricomincia il giro da capo?

D3. Rotazione in HOME: e' continua finche' c'e' intruso, oppure il DDR ruota
    di un angolo fisso e poi ricontrolla?

D4. Conoscenza della stanza: il DDR conosce le dimensioni a priori (mappa) o
    le deduce dai sensori a runtime?

Problematiche aperte (per l'analista)

P1 — Adapter o servizio? Per usare il VirtualRobot26 conviene RobotObj26 (POJO che nasconde il WebSocket) oppure RobotService26 (messaggi qak espliciti, piu' aderente al modello a microservizi)?
P2 — Modellazione del radar. Basta scrivere software sul PicoW, oppure serve un microservizio radaractor dedicato che intermedia tra PicoW e boundaryworker?
