Sprint 3: Conway Life - Transizione a Web GUI (HTML/JS)

Corso: Ingegneria dei Sistemi Software a.a. 2025/2026 - DISI - University of Bologna

1. Requisiti

Obiettivo: Evolvere l'interfaccia utente del progetto Conway's Game of Life (Progetto conway26GuiHtml).

Passare da una GUI desktop locale (implementata precedentemente in Java Swing) a una Web GUI distribuita basata su tecnologie standard (HTML, CSS, JavaScript) capace di comunicare con il backend tramite rete.

2. Analisi del Problema

Nei precedenti Sprint (1 e 2), il sistema era fortemente accoppiato alla macchina locale tramite Java Swing. Questo approccio monolitico limita l'accessibilità e non rispecchia l'architettura dei moderni sistemi distribuiti.

Per superare questo limite, è necessario separare il frontend dal backend. La sfida principale consiste nel mantenere la sincronizzazione in tempo reale della griglia (che si aggiorna frequentemente) tra il server (che esegue la logica di Conway) e il browser del client. L'uso di semplici richieste HTTP (polling) risulterebbe inefficiente; pertanto, si rende necessaria una comunicazione bidirezionale persistente.

3. Architettura Logica

L'architettura adottata trasforma il sistema in un'applicazione Client-Server moderna:

  • Backend (Server): Gestisce la logica core (matrice delle celle) e ospita un server web (es. Javalin) per fornire la pagina HTML iniziale. Inoltre, espone un endpoint WebSocket per la comunicazione real-time.
  • Frontend (Web GUI): Una pagina HTML arricchita con JavaScript. Usa le API native WebSocket del browser per ricevere gli aggiornamenti di stato dal server (es. cell(x,y,state)) e renderizzare visivamente la griglia (ad esempio tramite un elemento <canvas> o manipolazione del DOM).

4. Implementazione

Il componente fondamentale lato client è la gestione asincrona dei messaggi WebSocket:

// Esempio logico di connessione lato client (JavaScript)
const socketWS = new WebSocket("ws://localhost:8080/conway");

socketWS.onopen = () => {
    console.log("Connesso al server Conway");
    socketWS.send("Richiesta stato iniziale");
};

socketWS.onmessage = (event) => {
    // Il server invia aggiornamenti (es. in formato JSON)
    let update = JSON.parse(event.data);
    aggiornaGrigliaUI(update.x, update.y, update.state);
};

5. Testing e Risultati

Il collaudo ha dimostrato che l'architettura è robusta:

  • Aprendo http://localhost:8080 nel browser, l'interfaccia viene caricata correttamente indipendentemente dal sistema operativo.
  • I comandi inviati tramite bottoni HTML (Start, Stop, Clear) vengono interpretati dal server senza latenza percepibile.
  • Il disaccoppiamento è completo: è possibile aprire l'interfaccia su più browser contemporaneamente osservando lo stesso stato (se il server gestisce il broadcasting).
