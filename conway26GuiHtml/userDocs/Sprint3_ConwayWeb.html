ConwayLife Sprint 3 (Web GUI & WebSocket)

Introduction

GAME OF LIFE DI CONWAY
Goal: Transizione da un'applicazione Desktop Monolitica (Swing) ad un'architettura Client-Server distribuita con interfaccia Web (HTML/JS).

Requirements

R3  L'utente deve poter interagire con il sistema Conway tramite un normale Web Browser.
    Il sistema deve garantire l'aggiornamento in tempo reale della griglia mostrata nel browser
    mentre il motore di gioco (Backend) calcola le generazioni.

Requirement analysis

La separazione fisica tra Client (Browser) e Server (Backend Java) richiede l'uso di protocolli di rete standard. I componenti diventano:

  • Web Server (Inbound Adapter): Fornisce la pagina HTML statica e gestisce le connessioni in ingresso.
  • Frontend (Client): Pagina HTML arricchita con JavaScript per la manipolazione del DOM (rappresentazione della griglia) e l'invio di comandi.

Problem analysis

Il problema fondamentale è la sincronizzazione dello stato. L'approccio Request-Response standard (HTTP Polling) risulta inefficiente per un gioco che si aggiorna continuamente. È necessario stabilire un canale di comunicazione bidirezionale persistente utilizzando il protocollo WebSocket. In questo modo, il Server può inviare proattivamente (push) gli aggiornamenti di stato (es. cell(x,y,state)) al Client non appena una nuova generazione viene calcolata.

Test plans

Verifica della connessione Client-Server aprendo la pagina Web (http://localhost:8080) e simulando l'invio dei comandi Start/Stop/Clear, assicurandosi che la griglia risponda senza latenze percettibili e che la console del server registri i messaggi WebSocket in ingresso.

Project

Utilizzo del framework Javalin per implementare rapidamente sia il Web Server (per il delivery delle risorse statiche src/main/resources/public) sia l'endpoint WebSocket. Lato client, viene utilizzata l'API nativa WebSocket di JavaScript.

Testing

Test di concorrenza collegando più tab del browser contemporaneamente per verificare la stabilità del Web Server Javalin sotto carico di richieste asincrone.

Deployment

Il backend Java viene eseguito come servizio isolato. I client possono connettersi da qualsiasi dispositivo all'interno della medesima rete.

Maintenance

Il codice di interazione con Javalin agisce come un Adapter. La logica core di Conway (Sprint 1) rimane ancora una volta inalterata, garantendo elevata manutenibilità.
