Requirement analysis

Per il TODO 1, è necessario emacchettare l'applicazione Javalin in un'immagine containerizzata.
Per il TODO 2, occorre integrare la libreria unibo.basicomm23 e trasformare l'entità che esegue il calcolo in un Attore capace di gestire in modo asincrono l'invio e la ricezione di messaggi (IApplMessage).

Problem analysis

Nel TODO 1 (approccio monolitico), il server Web Javalin invocava direttamente la funzione di business eval(x). Il problema critico si manifestava con valori elevati (x > 4.0), dove un ritardo simulato (8 secondi) bloccava l'intero Web Server, causando errori di connessione per gli altri utenti.

Nel TODO 2, la soluzione architetturale impone l'uso di un Protoattore (MathActor). Il server web funge ora esclusivamente da Inbound Adapter (Clean Architecture): deposita i messaggi ricevuti via rete nella coda di input dell'attore. L'attore preleva ed elabora i messaggi in sequenza sfruttando un proprio Thread (Executors), lasciando il server Javalin libero di gestire nuove richieste immediatamente tramite l'uso di CompletableFuture.

Test plans

Inoltro di richieste multiple (es. /eval?x=5.0) tramite browser. La verifica del successo consiste nell'osservare i log della console: il server Javalin deve dichiarare di aver liberato il thread web, mentre l'attore esegue il calcolo asincrono restituendo infine la Reply (Risultato).

Project

Creazione del componente MathActor estendendo AbstractProtoactor26. Implementazione dei metodi contrattuali elabRequest (per restituire il risultato del calcolo) ed elabDispatch.

Testing

Verifica del formato dei messaggi costruiti tramite CommUtils.buildRequest() e dell'effettivo instradamento nel ProtoActorContext26.

Deployment

Dockerizzazione: È stato redatto un Dockerfile basato su eclipse-temurin:21-jdk. Tramite il task Gradle distTar è stato pacchettizzato l'applicativo, successivamente decompresso all'interno dell'immagine Docker per l'esecuzione del servizio isolato sulla porta 8080.

Maintenance

Il sistema risulta ora pienamente reattivo e distribuibile. La business logic è incapsulata in un attore autonomo, aprendo la strada all'applicazione di questo pattern architetturale (Protoattori) a sistemi più complessi, come il motore del gioco di Conway.
